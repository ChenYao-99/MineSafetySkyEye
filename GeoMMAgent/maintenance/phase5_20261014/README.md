# 报告专用角色工作流

2026-10-14完成真实接口验收并启用报告工作流。影像问答继续按任务选择角色。

## 单ReasoningAgent的原因

此前三条真实任务的调度计划本身只有ReasoningAgent，前端会逐条显示返回角色；这些样本没有丢失后续角色。通用调度规则偏好较少步骤，报告已有检测统计时不需要再次运行通用检测/分割，但旧角色集合缺少专用证据核查与报告复核。

## 当前行为

- 单期或ROI且采集日期已知：EvidenceAuditAgent → ReasoningAgent。
- 双期、日期缺失、证据冲突、占比不可计算或年度作业参考：增加ReportReviewAgent。
- 核查JSON的案例/请求/来源归属错误，或任一角色异常、截断、明确阻断时，不使用其输出继续后续步骤，交付带来源的事实降级。
- 前端分别显示按需单角色、多角色完成和链路中断；未执行角色明确标注，不补造协作卡片。
- 自评按配置默认关闭；它不替代原始证据或专业复核。

## 证据与评价边界

经用户单独授权最多14次，实际10次请求、28610 tokens。公开Las Cruces原开发影像的单期、双期、ROI三项链路均通过角色完整性、显式字段门禁、同次归档和JSON交接。实际执行角色分别为2、3、2个；单期及ROI另各触发一次引用格式修复，已计入请求。云端阶段重放既有GPU输出，不是新训练、新矿区或独立盲测。

这些任务证明角色确实执行、前序记录确实传递，不能证明普遍优于单角色，也不能认证报告的全部专业语义。内部复看仍发现核查角色会把已知条件重复列为未知、泛化疑点，双期净变化的不同显示精度表述也需继续改进。工程量测以原始工具字段为准，报告必须人工复核；当前不得声称矿方试用、专业用户验证或稳定跨矿识别已完成。

`cloud_acceptance.json`、`provider_receipts.jsonl`保留原始验收；`outbound_review_manifest.json`保留批准的提示和发送范围。`state.json`记录启用版本、最终回归、材料/权重保全和清理。候选验收时配置通过进程内开关启用，验收后仅将同一开关设置为默认开启。

下一阶段应使用新任务比较按需协同的语义质量和实际成本，并修正实际任务评估中的重复案例学习影响。旧任务已用于开发，不再作为未参与迭代的验收集。
