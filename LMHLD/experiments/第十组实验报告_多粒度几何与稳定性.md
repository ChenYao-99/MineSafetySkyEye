## 二、多粒度几何引擎（决策级任务变换）

### 2.1 设计

论文的核心主张是「单次推理经决策级任务变换同时产出多粒度结果，无需任务专属解码器」。落到本系统：

```
单次分割推理 → 掩膜 (H,W)
                 └── mask_to_regions()  ← 唯一的结构化几何入口
                        ├── 区域级：实例外接框 + 质心 + 面积
                        ├── 对象级：简化外轮廓 + 空洞 + 形态量（周长/长短轴/紧致度/长宽比/主轴方向/凸度）
                        └── 像素级：原掩膜（面积占比 / 风险分级）
```

**关键取舍：不做 MLLM 生成几何。** 论文的 Text2Mask 分支在本机不可行（单卡 RTX 4060 无法微调 MLLM），且其自身消融已证明结构化几何远胜文本几何（Bbox2Mask cIoU 60.25 vs Text2Mask 22.01）。我们把"决策级任务变换"落在**同一掩膜 → 三种粒度输出 + 统一几何口径**上。

### 2.2 实现中规避的两个致命坑

1. **形态量不用 `cv2.fitEllipse`** —— 它要求轮廓 ≥5 点，而 32px 图块中的滑坡常只有几个像素。任何未捕获异常会让整个 `/api/detect` 请求变成 500。改用 `cv2.moments` 的二阶中心矩特征值（均匀椭圆半轴 a,b 的二阶中心矩为 a²/4、b²/4，故 `4√λ` 恰为整轴长度）。
2. **返回值强制原生类型** —— numpy 2.0 下 `jsonify` 遇 `np.float32` 直接抛 `TypeError`。所有几何函数返回前一律 `int()/float()`，并在自测中用 `json.dumps` 断言（双环境各跑一遍：lmhld=numpy 2.0.1 / GeoMMA=1.26.4）。

**自测 35 项全部通过**，含退化输入（空/全/单点/3×3）、圆环空洞计数、贴边标记、JSON 可序列化、多边形回栅格保真（IoU 0.9905）。

## 三、E3 实验：三种粒度表达的信息损失

**协议声明**：本实验为 **GT→GT 的任务变换代价上界**，衡量"粒度本身能表达多少信息"，**不是模型精度**，不涉及任何模型。引用时必须标注。

在 6 区域共 **5020 个真实实例**上，把 GT 掩膜分别降级为外接框、降级为 eps=0.5 的简化多边形，再回栅格与 GT 比较：

| 区域 | 实例数 | 等效直径中位 | cIoU(掩膜) | **cIoU(多边形)** | cIoU(外接框) | 顶点数中位 |
|---|---|---|---|---|---|---|
| Emilia-Romagna（意） | 693 | 6.58 px | 1.0000 | 0.9637 | 0.5413 | 8 |
| Gorkha（尼） | 377 | 8.81 px | 1.0000 | 0.9834 | 0.5355 | 9 |
| Hokkaido（日） | 766 | 14.25 px | 1.0000 | 0.9897 | 0.4931 | 14 |
| Jiuzhaigou（九寨沟） | 612 | 17.15 px | 1.0000 | 0.9920 | 0.4844 | 18 |
| Wenchuan（汶川） | 705 | 30.90 px | 1.0000 | 0.9956 | 0.5249 | 31 |
| Taiwan（台湾） | 1867 | 25.18 px | 1.0000 | 0.9938 | 0.4595 | 29 |
| **全体（合并）** | **5020** | — | **1.0000** | **0.9939** | **0.4894** | — |

**结论**：
1. **多边形（eps=0.5）可还原 99.4% 的掩膜信息**，而**外接框只能还原 48.9%** —— 本数据集的滑坡多为碎裂/长条形，外接框会吞掉一半以上面积。
2. 因此系统内**面积/周长/形态量一律由实例多边形计算**，绝不使用外接框口径。这是论文"结构化几何 ≫ 文本几何"主张在本地数据上的量化支撑。
3. 附带测出**实例尺度分布**：32px 区域等效直径中位仅 6.6~8.8px，128/224 区域为 14.3~30.9px —— 这一事实决定了对象级边界指标只在后四个区域具备判别力（见第五节口径约束）。

## 四、系统接线与实证

### 4.1 检测服务（`detector_service.py`）

| 端点 | 新增能力 |
|---|---|
| `/api/detect`（数据集） | 响应携带实例几何；`num_regions` 改为真实计数 |
| `/api/detect_upload`（上传） | 同上 + 可选 `meters_per_pixel` → 米制量 |
| `/api/compare`（多期） | **实例级变化几何**：用包含度匹配判定"同一处滑坡是否扩大"，输出 `expansion_ratio`（扩大倍数） |
| `/api/geometry_export` | GeoJSON / CSV 导出 |

**匹配判据用包含度而非 IoU**：同一处滑坡扩大时 IoU 会因面积差必然下降，用 IoU 匹配会把「扩大」误判成「删除 + 新增」；包含度 `|A∩B|/min(|A|,|B|)` 对单向扩张稳定。

**修复的既有 bug**：`analyze_mask` 的 `num_regions` 原为 `len(region_areas)`，而 `region_areas` 只保留前 10 —— 实例数被**静默截断在 10**。抽样 177 个真实图块命中 6 个（旧代码报 10，实际 11/12/12/14/16 处）。已改为真实计数，同时保持 `region_areas` 仍为前 10（老消费者字节输出不变）。

### 4.2 后端（`backend.py`）：报告可信度的机制保障

**注入端**：把实例几何格式化为 ≤5 行/200 字的文本块注入提示词。长度硬约束是必需的 —— 此前提示词已多次触及 CAMEL 摘要阈值（实测最高 20953 vs 阈值 16384）。

**校验端**：报告质量守卫新增第 7 项「几何数字引用」（原 6 项一律不放松）。

**实测（九寨沟，真实链路）**：

```
实例: 面积 982px | 周长 223.82px | 长轴 101.14px | 紧致度 0.2463
守卫: 通过 | 缺失项: 无 | 告警: 无
报告引用的真实几何数字: ['982', '223.82', '101.14']   ← 全部命中
自评估: 通过
```

即：**报告数字来自几何工具计算，而非模型估计** —— 问题 2 在机制上被消除。

### 4.3 前端

新增：影像分辨率输入 + 元数据载入（直读 `fetch_mine_imagery.py` 的 `<景名>_meta.json`）、实例几何折叠块、矢量导出按钮（GeoJSON / CSV）、实例级变化明细。**有分辨率才显示平方米与米；数据集样本无地理参考，一律像素表达，不臆造米制数字。**

导出走同一个 Python 实现，前端只提交与下载 —— 不在 JS 里复写几何/大地计算，避免两侧实现漂移。实测导出往返：32 要素，面积 52864px = **221294.8 m²**（校验 52864×2.046² 精确吻合），经纬度 `[98.7094, 31.0822]`。

## 五、几何数字一致性校验的**能力边界**（如实记录）

越界判据经过两版迭代：

- **初版**（几何语境词 + 数字）**连续两次误报**：`面积占比为 3.1%`、`…面积的7倍` 都被"面积"这个词抓进来。自然语言里的几何语境词是枚举不完的。
- **现版**（只锚定带像素单位的数字）精度足够。依据：提示词中只有几何工具输出带像素量，知识库与通识建议只会出现米/公里/百分比。

**局限（已知且保留）**：该判据能抓"真实长轴 54.94px 却写 500 像素"这类**明显编造**，但**抓不到"贴着真值的杜撰"** —— 实测真实周长 179.3px 时，模型写"约 180 像素"落在 3% 容差内会被判为合法四舍五入。

因此该检查**只作软告警**（记入 `quality.warnings`），不进入缺失项、不触发修复循环（正则误判若触发修复会造成死循环）。**真正的防线是"把工具输出注入提示词"本身**，一致性校验只是兜底提示。测试中专门有一条用例断言该局限，而非假装它能做到。

## 六、稳定性根因修复（本轮最有价值的单项）

### 6.1 故障链（源码级定位）

先前把 19 场景中的 2 次调度失败归因为"JSON 格式错误率，与 ThinkGeo 报告的 30~44% 一致"。**该归因是错的。** 实测日志 + CAMEL 源码证明：

1. CAMEL 对 qwen 系模型默认 `token_limit=32768`、`summarize_threshold=50` → 阈值 **16384**；
2. 触发摘要时 `_build_conversation_text_from_messages` 对多模态消息的 list 型 content 做 `str()`，把 `data:image/png;base64,...` **整块拼进摘要提示词**（上传场景单图实测 513KB → base64 约 68 万字符），远超 qwen-vl-max 的 129024 token 上限 → 400；
3. 摘要失败返回空串，但上游**不检查成败**即调用 `_update_memory_with_summary`；
4. 该方法用 `isinstance(content, str)` 取"最后一条用户消息"，而多模态 content 是 **list** → 判断失败 → `last_user_message=None`；
5. `clear_memory()` 清空全部记忆只留 system，恢复步骤被跳过 → 下次调度发出 `[system, assistant("")]` → **无 user 角色** → 400 → 表现为 `Dispatch parsing failed`。

**旁证**：日志中"Token count 17251"与摘要载荷上千万字符相差 4 个数量级 —— 因为本地 token 计数对图像用的是 OpenAI 视觉公式（按 512px 方块估算），从不计 base64 文本长度。

### 6.2 修复（两处 monkeypatch，带 import 守卫，不阻断启动）

1. **摘要文本只取文字部分**，图像以 `[图像]` 占位 —— 消除第一个 400；
2. **空摘要不更新记忆**（安全网）+ **补偿恢复最后一条用户消息** —— 关键点：即使摘要成功，上游的 `isinstance(str)` 判断仍会漏掉多模态消息，记忆照样被清空到无 user 角色。**只修摘要不够。**

回归测试 20 项（从 `backend.py` 源码提取函数原文执行，避免测试与线上代码失真）。关键验证：喂入 70 万字符 base64 载荷，摘要文本从"爆掉"降到 **41 字符**。

### 6.3 验证：19 场景回归对比

| 指标 | 加固后（上一轮） | **本轮（根因修复后）** |
|---|---|---|
| 场景成功 | 19/19 | **19/19** |
| 报告要点命中率 | 1.000 | **1.000** |
| 守卫通过率 | 0.947 | **1.000** |
| 降级率 | 0.053 | **0.000** |
| 自评估通过率 | 0.895 | **0.947** |

| **In-Order** | 0.224 | **0.645** |

**耗时上升 15 秒是修复的结果而非退化**：步数从 2.95 升到 3.63，因为记忆不再被摘要故障清空后，协调器能把完整计划走完。序列指标（Exact-Match 0→0.421）的跃升同源 —— 先前的"短序列"其实是记忆受损的表现。

## 八、结论与可引用要点

1. **多粒度输出**：单次分割推理经决策级任务变换同时产出区域级（外接框）、对象级（简化多边形与形态量）、像素级（风险掩膜）三种粒度，无任务专属解码器；
2. **粒度代价**：多边形（eps=0.5）可还原 **99.4%** 的掩膜信息，外接框仅 **48.9%**（6 区域 5020 实例，GT→GT 上界）→ 面积/周长一律由实例多边形计算；
3. **报告可信度**：几何量经工具计算后注入提示词，报告真实引用（实测 982 / 223.82 / 101.14 全部命中），"编造尺寸"在机制上被消除；一致性校验作为兜底，其能力边界如实标注；
4. **稳定性根因**：调度失败的真因是**摘要故障级联清空记忆**（非 JSON 格式问题），修复后调度失败 0/5，序列指标 Exact-Match 0→0.421；
5. **可量测性**：系统具备实例级量测与矢量输出能力（GeoJSON/CSV，含经纬度与米制量），可对接 GIS 与方量测算流程。
